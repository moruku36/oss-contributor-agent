# 決定記録：PR提出ゲート（2026-11-07）

## 決定（オーナー：森健太郎）

- **PRの提出は、オーナー本人の判断を必須のゲートとする。** エージェントおよび開発側（フワッチ）は、PRを自律的に提出しない。
- ゲートより前の工程は、フワッチ側で自律的に進めてよい：
  1. 候補の選定（候補プールから）
  2. サンドボックスでのパッチ生成（Phase 2：Coder Loop、Docker隔離、TDD）
  3. テストの実行と結果の記録
  4. コンプライアンス確認（Phase 3：対象リポジトリの CONTRIBUTING・ライセンス・既存PR重複チェック）
  5. PR下書き（タイトル・本文・差分）の作成

## ゲートでの提示物

オーナーが短時間で判断できるよう、PRごとに次を揃えて提示する：

- 対象リポジトリと Issue（リンクと要約）
- パッチの差分
- テスト結果（実行コマンドと合否）
- コンプライアンス確認の結果

## 自制ルール（元論文 "Regulating the Machine Contributor" の趣旨）

- 提出ペースには上限を設ける（週あたりの上限は Phase 3 設計時に定める）。
- 却下率が高まったら自動で絞る／止める。
- 同一リポジトリへの連続提出にはクールダウンを置く。
